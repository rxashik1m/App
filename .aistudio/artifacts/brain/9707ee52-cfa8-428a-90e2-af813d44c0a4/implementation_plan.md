# AppForge AI — Universal AI Project to Android APK/AAB Converter

AppForge AI is a universal AI-generated project to Android application converter platform. It ingests source code archives created by any AI coding assistant (Google AI Studio, Cursor, Claude, ChatGPT, Bolt.new, Lovable, v0, Windsurf, Replit), automatically identifies frameworks and dependencies, configures Android scaffolds across dedicated build pipelines, executes compilation and signing workflows, provides real-time streaming build logs, and delivers production-ready APK and AAB downloads with automated temporary file lifecycle cleanup.

---

### User Review & Critical Decisions

> [!IMPORTANT]
> The platform is architected as a high-performance Android Studio & Converter Application with an on-device project scanner, local conversion & validation engine, real-time build simulation & orchestration pipeline, and pre-configured Firebase/cloud worker integration points.

- **Confirmed Decision 1: Hybrid Universal Architecture**: The application runs natively on Android with an interactive on-device scanner and builder engine capable of ingesting real ZIP archives from device storage, extracting safely, analyzing manifest and package configurations, generating Android wrappers (Capacitor/Gradle), and running compilation pipelines.
- **Confirmed Decision 2: Built-in AI Project Templates**: In addition to standard device file picker ZIP uploads, AppForge AI comes with preloaded reference projects generated by major AI tools (Google AI Studio React/Vite, Claude HTML5, Cursor Native Compose, Bolt.new Fullstack, v0 Next.js) so users can immediately test the scanner, customization panel, build logs, and APK generator.
- **Confirmed Decision 3: Zero-Retention Security & File Deletion**: In accordance with enterprise conversion standards, uploaded project files and temporary build artifacts are isolated in transient sandboxes with an automated 24-hour expiration policy and immediate post-download purge triggers.

### 1. Overview & Core Concept

- **What It Does**: AppForge AI bridges the gap between AI-generated codebases and native Android distribution. Users upload any AI project archive (ZIP); the universal scanner automatically categorizes framework type, entry points, configuration manifests, and dependencies; the customization engine provides deep control over package naming, icons, SDK levels, and Android permissions; the build engine compiles and signs APKs and AABs with live streaming console logs; and the download center provides signed binary packages.
- **Target Audience / Persona**: Developers, prompt engineers, indie hackers, and creators using AI coding tools (Google AI Studio, ChatGPT, Claude, Cursor, v0, Lovable, Bolt.new) who need fast, zero-headache Android packaging without manually configuring complex Android SDKs, Gradle wrappers, or Capacitor toolchains.
- **Key Value**: Eliminates manual build configuration failures, handles web-to-Android and native Gradle pipelines automatically, explains errors with AI-assisted diagnostics, and strictly enforces source code privacy through automated file deletion.

### 3. Key Product Decisions & Trade-Offs

- **Decision 1: Six Dedicated Framework Conversion Pipelines**:
  - *Approach*: Implement dedicated pipeline modules for HTML/JS (Capacitor), React/Vite/Vue (Node build + Capacitor), Native Android (Direct Gradle packaging), Flutter (Dart build), React Native (Metro + Android wrapper), and Fullstack (Frontend packaging + API gateway endpoint mapping).
  - *Why*: Prevents native Android projects from being wrapped in unnecessary WebViews, while giving web projects proper modern Capacitor Android containers.
- **Decision 2: Comprehensive On-Device Project Scanner & Validator**:
  - *Approach*: Built-in parser for `package.json`, `vite.config`, `pubspec.yaml`, `build.gradle`, and `AndroidManifest.xml` with automatic zip inspection, bomb prevention, and path-traversal sanitization.
  - *Why*: Allows instantaneous analysis of uploaded archives directly on device with zero latency before initiating heavy compilation.
- **Decision 3: Room Database for Local Build History & Worker Queue**:
  - *Approach*: Persistent Room entities for user builds, scan reports, and worker configurations, coupled with Firebase integration contracts for cloud scaling.
  - *Why*: Ensures seamless offline operation, fast local caching, and reliable state preservation between app sessions.

### 5. Implementation Phases & Milestones

1. **Phase 1: Project Metadata & Navigation Core**
   - Synchronize `metadata.json` and `res/values/strings.xml` to `AppForge AI`.
   - Setup navigation model covering all 10 core screens with predictive back-handling and state preservation.

2. **Phase 2: Data & Engine Layer**
   - Room Database implementation (`AppForgeDatabase`, `BuildJobDao`, `ScanReportDao`).
   - `ProjectScannerEngine` with zip extraction safety, framework detection, and security audit.
   - `ConversionPipelineEngine` implementing Pipelines A, B, C, D, E, and F.
   - `RetentionCleanupManager` enforcing automatic 24h expiration and post-download purging.

3. **Phase 3: High-Fidelity UI Suite**
   - **Landing & Dashboard**: Metrics, quick upload CTA, recent build history, AI generator badges.
   - **Upload & Scanner**: Interactive drag/drop simulator, real file picker, preloaded AI test archives.
   - **Customization Studio**: Package ID validator, SDK selectors, permission checkboxes, theme picker.
   - **Live Build Console**: Multi-stage progress indicators, streaming ANSI terminal logs, failure diagnostics.
   - **Download Center & QR**: Signed APK/AAB distribution cards, SHA-256 integrity, install instructions.
   - **Retention & Settings**: Active storage monitor, auto-purge timers, signing keystore manager.
   - **Admin Telemetry**: Worker pool health, build queues, error tracking.

4. **Phase 4: Build Verification & Compilation**
   - Compile and verify with `compile_applet`.
   - Validate CUJs including real archive scan, customization, build simulation, and artifact download.
